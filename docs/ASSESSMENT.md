# 一、项目现状

## 1.1 总体评价

Orion Agent 是一个约 2.4 万行 Dart 的 Android 单端 AI Agent 应用  
（Flutter + Riverpod + Drift/SQLite + Dio），核心差异化能力为  
proot Linux 终端、本地 RAG 知识库、全本地化数据。

**优势**（应当保持并在升级中保护）：

- 服务层健壮性经过 88 项已修复缺陷的锤炼，协议细节（SSE、MCP、Edge TTS）  
  的边界处理在同规模项目里属高水平，且全部有档案可查（PROJECT.md §11）
- 单元测试 18 个文件、约 1,300 行，覆盖了历史上炸过的所有点位
- CI 全自动（analyze/test/build/APK/Release 一条龙），本地无 Flutter SDK  
  的约束被工程化地解决了
- 文档文化极强，每个修复都有根因记录

**主要短板**（本报告第二、三部分展开）：

- 启动全量加载与会话内存模型的扩展性到头了（会话/图片一多必然劣化）
- RAG 仍是 O(n) 全表暴力检索，知识库规模受限
- 两个核心功能是"App 内实现"而非"系统级实现"（定时调度、通知触发）
- UI 层缺少无障碍、错误提示形态单一、个别超大文件难维护
- 工程上 pubspec.lock 不跟踪、lint 偏松、无崩溃上报，问题发现依赖用户反馈
- 文档已出现滞后（如 PROJECT.md §7.3 仍称任务页为占位页，实际已实现 611 行）

## 1.2 架构与模块划分

```
UI 层 lib/ui/（25 文件，约 1.3 万行）
  home_shell（4 Tab + 抽屉 + 磨砂底导航）→ chat / tasks / skills / profile
  配套页：settings、cloud_account、terminal、knowledge、mcp、roles、
         appearance、tts_settings、storage、about、token_stats、setup…
        ↓ Riverpod
状态层 lib/providers/providers.dart（1,710 行，全部 provider 集中一处）
        ↓
服务层 lib/services/（19 文件，约 6,700 行）
  llm_client（SSE）→ agent_orchestrator（ReAct ≤8 轮）→ tools（7 内置工具）
  mcp_client/mcp_service（Streamable HTTP，仅 tools 能力）
  rag_service + text_chunker（向量检索）、memory_service（长期记忆）
  terminal_service（proot，Alpine/Debian）、voice_service（Edge TTS + ASR）
  cloud_service（账号/卡密/设备/更新中继）、token_stats_service
  storage_service、database（Drift schemaVersion 9，11 张表）
        ↓
数据层：SQLite（orion_agent.sqlite）+ SharedPreferences（设置项）
       + FlutterSecureStorage（API Key / 云端 JWT / 设备令牌）
```

分层清晰、依赖方向正确（UI→状态→服务→数据），无循环依赖。  
**结构性问题**有两处：

| #  | 问题                                                                                | 位置                             | 说明                                       |
| -- | --------------------------------------------------------------------------------- | ------------------------------ | ---------------------------------------- |
| A1 | **providers.dart 单文件 1,710 行**，聊天/配置/TTS/通知/主题/任务/云端全部 provider 集中                | `lib/providers/providers.dart` | 新人定位难、改动影响面不清晰，是当前最大的"改动风险放大器"           |
| A2 | **三大 UI 巨石文件**：chat_screen 1,941、settings_screen 1,650、cloud_account_screen 1,214 | `lib/ui/`                      | 内部虽按私有 widget 组织，但单文件改动时 diff 审查与回归范围都过大 |

# 四、实施路线（分阶段计划）

> 原则：每阶段独立可发版（版本号照常递增）；先打地基后盖楼；
> 性能项与功能项凡是"同文件同批次"的合并做；遵守 PROJECT.md 附录 B
> 文档维护约定，每阶段结束同步更新文档。

## 阶段 0：工程底座（0.5~1 个版本，预计 v0.2.8）

**目标**：让后续所有改动更安全、可复现、可观测。
**范围**：

1. 提交 `pubspec.lock`，锁定依赖（M1）
2. 文档纠偏：PROJECT.md §7.3/§12/§14/附录 A 与现状对齐（M5）
3. 轻量日志层落地：统一 debugPrint → AppLog（级别 + 环形缓冲 + 文件落盘开关），关于页加"导出诊断日志"（S3/M3/F4）
4. lint 收紧第一档：恢复 unused 告警；`prefer_const_constructors` 在新拆分模块内启用（Q4，分步走避免一次性巨量 diff）
5. 发版脚本读取 pubspec 版本校验 `kAppVersion` 一致（Q7）

**验收**：CI 全绿；新日志在真机上可导出；文档与代码一致。

## 阶段 1：数据层现代化（1 个版本，v0.2.9）

**目标**：解决启动/存储两大扩展性瓶颈，为搜索与备份铺路。
**范围**：

1. 会话列表分页 + 消息按会话按需加载（P1，Drift 查询改造 + 抽屉改造）
2. 消息图片迁移出 DB：`<appSupport>/images/` 文件存储 + DB 存路径 + 旧数据一次性迁移（P2，schemaVersion 9→10）
3. 会话搜索（标题 + 内容 LIKE，量级上来后升 FTS5）（F3/U5）
4. 错误信息结构化第一版（AppError，Q6）

**风险控制**：迁移必须有"迁移前自动备份 DB 文件"与失败回退；分页改造配套 storage_test 回归。

**验收**：1,000+ 会话模拟数据下启动 < 1s、内存占用平稳；旧数据升级无丢失。

## 阶段 2：功能补齐（1~2 个版本，v0.3.x）

**目标**：把两大卖点补到实用级。
**范围**：

1. 知识库文件导入（F1/U1）：file_picker + PDF（pdfx 或类似纯 Dart 方案）/Markdown/txt 解析 → 复用 text_chunker；文档分块预览页
2. 定时任务 WorkManager 化（F2/U3）：原生 MethodChannel 扩展 + 与现有 task_rows/补跑逻辑融合；App 存活期 tick 保留为精确分钟级补充
3. 对话导出/分享（F5/U6）
4. TTS 音色试听（U7）+ 流式失败重试 + 消息长按菜单（F9/U4/U8）
5. UI 巨石第一刀：chat_screen 拆分（Q2，随本阶段对话页改动顺带完成）

**验收**：导入一份 50 页 PDF 可检索可溯源；杀进程后每日任务照常触发。

## 阶段 3：Agent 能力与安全（1~2 个版本，v0.4.x）

**目标**：Agent 循环的可靠性、安全性与可测性上一个台阶。
**范围**：

1. 工具执行确认机制（F7/S1）：风险分级 + 确认卡 + 可配置白名单
2. MCP resources 支持（F6）
3. 伪 LLM SSE 服务 + Agent 主链路集成测试 + Orchestrator 单测补齐（M4/F13）
4. providers.dart 按域拆分（Q1/M12，纯移动代码不改逻辑，测试护航）
5. 多模态拍照入口（F10）

**验收**：危险命令触发确认卡；mock LLM 驱动的端到端测试进 CI。

## 阶段 4：性能深化与加固（v0.5.x，可与用户反馈穿插）

**目标**：规模化与防护。
**范围**：

1. RAG sqlite-vec + docId 过滤 + embedding 缓存（F11/P3）
2. 混淆/加固重引入（F8）：独立测试版 → 真机验证 → mapping/symbols 取证 → 正式版（严格按 §11.18 流程）
3. settings/cloud_account 页拆分（Q3）；无障碍补全（U2，随各页改动顺带）
4. 云端 https 强制与警告（S2）、搜索后端可配置（S5）
5. 记忆分层 / 角色会话级 / 技能参数化（F14~F16，按用户反馈排入）

**长期观察项**：targetSdk 演进（S4）、Flutter stable 升级窗口、Android 目录入库后的 CI 简化（M2 亦可提前至阶段 1 执行，视 CI 稳定性需求决定）。
